Agent 记忆系统 ​

概述 ​

为任意项目创建 .memory/ 目录结构，实现跨 AI 工具、跨会话的项目长期记忆。不需要任何外部依赖，纯 Markdown 文件系统。

核心理念：不保存完整聊天历史，而是将有用的上下文（决策、约定、进度、偏好）序列化为简洁、可检索的 Markdown 文件。.memory/AGENTS.md 是唯一入口——AI 只需读这一个文件，就知道项目的一切和会话工作流。

支持工具：WorkBuddy、Cursor、Codex、Claude Code、GitHub Copilot 等任何能读写文件的 AI 编码助手。

初始化项目记忆 ​

有两种初始化方式：

方式一：运行 init 脚本（优先） ​

bash
python scripts/init_memory.py [项目根目录] [--desc "项目描述"] [--stack "技术栈,逗号分隔"]

示例：

bash
python scripts/init_memory.py ./my-project --desc "宠物医院预约系统" --stack "Python,FastAPI,SQLite,Vue3"

脚本会：

  1. 在项目根目录创建 .memory/ 目录结构
  2. 复制所有模板文件并自动填充项目名称
  3. 如果传了 --desc，将项目描述写入 AGENTS.md（替换占位提示）
  4. 如果传了 --stack，将技术栈填入 AGENTS.md 技术栈表格
  5. 自动检测 AI 工具配置文件（.cursorrules / CLAUDE.md 等），不存在则创建引用行，存在但未引用则警告
  6. 不覆盖已有的 .memory/（安全保护）

方式二：手动复制模板 ​

从 assets/templates/ 复制以下文件到项目 .memory/ 目录：

text
.memory/
├── AGENTS.md                 # 唯一入口（项目身份 + 工作流指令，每次会话必读）
├── context/
│   └── decisions.md          # 技术决策日志
└── working/
    ├── todo.md               # 进度跟踪
    └── plan.md               # 实施计划（可选）

工具适配指南 ​

关键前提：AI 工具不会自动读取 .memory/。你需要在工具的配置文件中加一行引用。

不同工具引用 .memory/ 的方式——只需一行，让 AI 在每次会话自动读取 AGENTS.md：

工具配置位置写入内容
Cursor项目根 .cursorrules每次会话开始时，先读取 .memory/AGENTS.md。
Claude Code项目根 CLAUDE.md同上
WorkBuddy项目根 AGENT.md 或 .workbuddy/rules/同上
Codex/Windsurf项目根 .windsurfrules同上
Copilot.github/copilot-instructions.md同上

AGENTS.md 已内置完整的启动/收尾工作流和决策记录格式，AI 读完后自然知道该做什么——零复制粘贴。

日常工作流 ​

新会话启动时 — 分层读取 ​

不要无脑读全部 5 个文件。按任务性质分层：

层级文件触发条件
必须读.memory/AGENTS.md所有任务（项目身份、技术栈、关键约定）
继续开发时读.memory/working/todo.md、.memory/working/plan.md继续昨天的开发、修复 bug、实现新功能
牵涉架构时查.memory/context/decisions.md做技术选型、修改核心模块、重构时搜索相关决策（不全量加载）

会话结束时 — 记忆收尾（必做） ​

  1. 更新进度：编辑 .memory/working/todo.md
    • 完成的阶段/任务 → 打勾 [x]
    • 更新「当前位置」描述
  2. 记录决策：如果有新的技术决策 → 追加到 .memory/context/decisions.md
    • 格式：[日期] [分类] 决策项 → 选定方案 | 原因 | via:来源
  3. 同步计划：如果 plan.md 存在 → 更新计划状态

记忆文件规范 ​

AGENTS.md — 唯一入口 ​

包含章节：

  • 项目概述（一两句话）
  • 技术栈（表格，首次技术选型后填写）
  • 关键约定（开发中逐步添加）
  • 记忆文件索引（含"何时读"指引）
  • 会话工作流（启动步骤 + 收尾步骤 + 决策记录格式）

初始状态：各章节只留引导提示（斜体），在开发过程中由 AI 或用户增量填充。

设计意图：AI 只需读这一个文件，就能知道项目身份、记忆文件在哪、会话如何启动和收尾。无需复制粘贴任何内容。

context/decisions.md — 技术决策日志 ​

写入时机：任何影响架构、技术栈或设计模式的选择。

格式：[YYYY-MM-DD] [分类] 决策项 → 选定方案 | 原因 | via:来源

分类标签：

  • [架构] — 系统架构、模块划分、数据流设计
  • [工具] — 依赖选择、库选型、第三方服务
  • [约定] — 代码规范、命名约定、流程约定
  • [性能] — 性能优化相关
  • [安全] — 安全策略与措施

示例：

markdown
- [2026-07-03] [工具] 数据库选型 → SQLite | 单用户低并发，减少运维成本 | via:Codex
- [2026-07-04] [架构] 放弃 Redis → 内存缓存 | 数据量 < 100MB，Redis 运维开销 > 收益 | via:WorkBuddy
- [2026-07-05] [约定] API 响应格式统一 → {code, data, msg} | 前端统一处理 | via:Cursor

working/todo.md — 进度跟踪 ​

结构：进度总览表（阶段｜名称｜状态｜完成时间）+ 待办清单（复选框）。

状态值：⬜ 未开始 | 🔄 进行中 | ✅ 已完成 | ⏸️ 暂缓

working/plan.md — 实施计划（可选） ​

创建时机：当前阶段需要 3+ 步骤时才创建。完成后归档到 .memory/archive/ 或删除。

写入原则 ​

  1. 简洁具体 — 不复制代码或对话，只记录要点和结论
  2. 可检索 — 使用清晰的标题和关键词；decisions 用分类标签
  3. 可对比 — 重要决策记录备选方案和理由
  4. 有时效 — 标注日期，过时信息及时更新
  5. 不含敏感信息 — 不存储密钥、凭证等
  6. 标记来源 — 使用 via:来源 标记写入者

定期维护 ​

周期操作
每次会话结束更新 todo.md + 追加 decisions（如需要）
每个阶段完成清理 todo.md 已完成条目，归档 plan.md
每季度审查 decisions.md：超过 90 天且已固化到代码的决策 → 移到 archive/decisions-YYYY-QX.md；审查 AGENTS.md 技术栈和约定是否与代码一致

何时需要创建 .memory ​

需要创建：

  • 多文件迭代的项目（3+ 文件）
  • 需要跨天/跨会话持续开发的
  • 涉及技术决策和架构选择的
  • 有明确开发阶段的

跳过：

  • 一次性脚本
  • 单轮问答
  • 不涉及文件修改的对话

设计哲学 ​

本系统采用项目级独立记忆，每个项目自带 .memory/，不依赖全局记忆层。理由：

  • 日常开发通常只需专注 1-2 个项目
  • 项目级记忆随代码一起保留，不污染其他项目
  • 无需维护跨项目的全局状态
  • .memory/ 目录可作为项目资产的一部分直接拷贝、打包、归档
