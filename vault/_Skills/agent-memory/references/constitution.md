# Agent 记忆系统详细规范

> 本文档是模板文件的详细设计说明书，解释每个字段和规则的意图。

## 设计哲学

### 为什么不保存完整聊天历史

聊天历史会腐烂。三个月前的对话细节今天看毫无意义。但从中提炼出的**决策、约定、偏好**可以保鲜数年。

**记忆系统的目标**：把 AI 编码助手的上下文序列化为简洁、具体、可检索的 Markdown 文件，在不同 Agent、不同会话之间保持连续性。

### 跨 AI 工具兼容性

本规范设计为**框架无关**：
- WorkBuddy / Cursor / Codex / Claude Code / Copilot — 任何 AI 编码工具都能读写
- 所有文件都是纯 Markdown，不依赖任何特定工具的 API
- 唯一依赖：文件系统读写权限

**关键前提**：AI 工具不会自动读取 `.memory/`。必须通过工具配置文件引用（详见 SKILL.md > 工具适配指南）。

## 目录结构详解

```
.memory/                          # 项目根目录下的隐藏目录
├── AGENTS.md                     # 唯一入口 — AI 会话的必读文件，含项目身份 + 工作流指令
├── context/                      # 上下文记录
│   └── decisions.md              # 技术决策日志（按日期追加，带分类标签）
├── working/                      # 进行中的工作
│   ├── todo.md                   # 进度跟踪
│   └── plan.md                   # 当期实施计划（可选）
└── archive/                      # 历史存档
    ├── decisions-YYYY-QX.md      # 按季度归档的旧决策
    └── plan-{阶段名}.md          # 已完成阶段的计划
```

### AGENTS.md

**用途**：AI Agent 的「项目入职文档」，也是**唯一入口**。每次新会话的必读文件。

**自包含性**：AGENTS.md 不仅含项目身份和约定，还内置了完整的会话工作流（启动时读什么、收尾时写什么、决策记录格式）。AI 读这一个文件即拥有全部操作知识，**无需复制粘贴任何额外指令**。

**设计决策**：
- 初始化为**骨架**而非**占位模板**：不加 `[待填写]`，用斜体引导提示，AI 和人在开发中增量填充
- 这是刻意设计——新项目在开始写代码之前，不知道技术栈和约定是什么
- 第一版只包含项目名称和记忆文件索引；其余在开发中长出来

**不是**：README.md（给人看的）、CONTRIBUTING.md（贡献指南）。AGENTS.md 是写给 AI 的。

### context/decisions.md

**用途**：技术决策的记录与追责。

**格式**：`[YYYY-MM-DD] [分类] 决策项 → 选定方案 | 原因 | via:来源`

**分类标签**：
- `[架构]` — 系统架构、模块划分、数据流
- `[工具]` — 依赖/库/第三方服务选型
- `[约定]` — 代码规范、命名、流程
- `[性能]` — 性能优化策略
- `[安全]` — 安全策略与措施

**维护**：每季度归档超过 90 天的已固化决策至 `archive/decisions-YYYY-QX.md`。

### working/todo.md

**用途**：开发进度跟踪。每次会话结束时更新。

**格式**：进度表（阶段 | 状态 | 完成时间）+ 当前位置描述 + 待办复选框。

**维护**：每个阶段结束后清理已完成条目。

### working/plan.md（可选）

**用途**：当前阶段的详细实施计划。任务需要 3+ 步骤时创建，完成后移至 `archive/`。

## 操作规范

### 写入时机

| 信息类型 | 写入目标 | 示例 |
|---------|---------|------|
| 技术决策 | `context/decisions.md` | 「放弃 Redis 改用内存缓存，因为数据量 < 100MB」 |
| 项目约定 | `AGENTS.md` | 「所有函数必须写类型注解」 |
| 进度更新 | `working/todo.md` | 「阶段二已完成，进入阶段三」 |
| 实施方案 | `working/plan.md` | 任务需要 3+ 步骤时创建 |

### 读取策略（分层，避免浪费 token）

| 层级 | 文件 | 触发条件 |
|------|------|---------|
| 必须读 | `AGENTS.md` | 所有任务 |
| 继续开发时读 | `working/todo.md`、`working/plan.md` | 继续昨天的工作 |
| 牵涉架构时查 | `context/decisions.md` | 做技术选型、修改核心模块、重构时**搜索**而非全文加载 |

### 写入原则

1. **简洁具体** — 不复制代码或对话，只记录要点和结论
2. **可检索** — 使用清晰的标题、关键词和分类标签
3. **可对比** — 重要决策记录备选方案和理由
4. **有时效** — 标注日期，过时信息及时更新或归档
5. **不含敏感信息** — 不存储密钥、凭证等
6. **标记来源** — 使用 `via:来源` 标记写入者

## 并发与冲突处理

- 支持多个 Agent 顺序使用，但**不建议同时写入同一文件**
- 若可能发生并发写入：各 Agent 写入独立的临时文件，人工合并
- 写入前若发现文件已被其他 Agent 修改，提示用户处理

---

## 架构选择：项目级独立记忆

本系统刻意设计为**纯项目级**，不依赖全局记忆层：

- **.memory/** 是自包含的：每个项目的记忆目录完整独立，不引用外部文件
- **专注性**：日常开发通常只专注 1-2 个项目，全局记忆层增加维护负担而收益有限
- **可迁移性**：整个项目目录（含 .memory/）可以直接拷贝、打包、归档，不丢失上下文
- **简化心智模型**：不需要在「全局记什么、项目记什么」之间做选择
