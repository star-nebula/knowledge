# AI中转站-模型路由与成本优化

API茶馆在原文 §2.2 中将路由解释为决定请求发往哪个模型或通道，并讨论四种方式：

| 方式 | 原文描述 |
| --- | --- |
| 直接映射 | 按用户指定的模型转发 |
| 按任务选模型 | 根据任务复杂度选择效果达标、成本较低的模型 |
| 通道切换 | 服务不稳或渠道价格变化时切到备用通道 |
| 模型降级 | 高峰限流时将部分非核心请求转到备用模型 |

原文 §2.3 还列出缓存已有答案、精简 Prompt、合并小请求等技术降本方式。请求合并的节省被限定在某些按次计费场景，不能据此推导 Token 成本必然减少。

作者声称路由可降本 20%～40%、缓存命中率可达 5%～15%，但文章未提供实验或样本，故不将这些比例作为容量或收益预测依据。“较小模型效果相同”也只是文中举例，未经本次测试。

整理者提醒：同模型通道切换与更换模型是不同操作；指定模型被替换时应明确告知调用方。缓存是否可复用还要核对上下文、参数与数据隔离条件；这些是补充提醒，并非原文已给出的完整实现方案。
