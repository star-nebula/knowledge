# 原子笔记编写规范

> 本规范定义原子笔记的编写标准。
> 原子笔记是知识体系的最小语义单元——一个笔记只承载一个独立概念。

---

## 前置速查：每次操作前的核心规则

以下规则摘自原 `rules-core.md`，已适配当前知识库结构：

### 1. Frontmatter 必填
所有知识页面必须包含 YAML frontmatter，使用以下字段体系：

```yaml
---
title: <核心概念>
created: <YYYY-MM-DD>
tags:
  - <主题标签>
type: 概念解释  # 概念解释 / 步骤操作 / 对比分析 / 故障排查 / 面试知识点 / 极简速记 / 专题聚合页 / 模板
related:
  - "[[关联笔记]]"
reference:
  - "[[来源笔记]]"
---
```

### 2. 标题规范
文件名 = 标题，使用简洁明确的名词短语。详见 [3.1 标题规则](#31-标题规则)。

### 3. 链接规范
内部用 wikilink、外部用标准 Markdown 链接。详见 [5 链接规范](#5-链接规范)。

### 4. 笔记粒度原则
- 独立知识点 → 单独成文
- 同类知识点 → 聚合成主题笔记
- 判断标准：经常一起参考 → 聚合；相互独立 → 原子化

### 5. 核心内容自包含
以下内容必须写在笔记内部，不能只放外部链接：代码示例、关键配置、踩坑记录

### 6. 外部链接标注访问日期
`[Python装饰器文档](https://...)（访问于 2026-05-22）`

### 7. 索引页禁止元说明
索引页（type: 专题聚合页）正文中禁止出现"由原大文件拆分为 N 篇"等拆分声明

### 8. 可选扩展属性
除「前置速查 1」定义的 6 个标准字段（`title` / `created` / `tags` / `type` / `related` / `reference`）外，以下属性可在手写笔记时选用：

| 属性 | 说明 | 与标准字段的关系 |
|------|------|-----------------|
| `aliases` | 别名列表，供搜索命中 | 无对应 |
| `source_type` | 资料来源分类（课程笔记/个人原创/技术文档） | 补充 `reference`（来源性质） |
| `source_path` | 原始文件相对路径 | 补充 `reference`（来源位置） |
| `author` | 作者标识（多人协作时） | 无对应 |

## 1. 核心原则

### 1.1 原子性：一个笔记 = 一个最小知识闭环

原子笔记的核心不是"越小越好"，而是**构成一个完整的知识闭环**——读者读完能获得一个可用的认知单元。

#### 最小知识闭环原则

拆分笔记时必须同时满足三个条件，缺一不可：

1. **单一性**：只回答一个问题或解释一个独立概念
2. **完整性**：拆分后的每篇笔记都有开头有结尾，不残留"没说完"的内容
3. **有用性**：单独拿出来仍有价值，不是"必须和另一篇一起看才成立"

**禁止无意义超碎拆分**——以下情况不应拆分：
- 一个概念的核心定义和它的典型示例 → 同一篇（示例是定义的完整性组成部分）
- 一个操作的前置条件和操作步骤 → 同一篇（条件是步骤的完整性组成部分）
- 一组密不可分的对比项（如 GET 与 POST 的区别）→ 同一篇（拆开后任一方失去对比语境）

#### 强从属内容不可拆分 vs 独立内容必须拆分

| 判断标准 | 示例 | 操作 |
|---------|------|------|
| **强从属**：B 离开 A 就失去意义或产生歧义 | "HTTP 缓存机制"的概念 + 缓存头字段列表 | **不拆**，合为一篇 |
| **强从属**：B 是 A 的固有组成部分，不是独立知识 | "Python 装饰器"的定义 + 基本语法 | **不拆**，合为一篇 |
| **独立**：B 拿出来单独看仍有完整价值 | "Python 装饰器" vs "Python 装饰器实战案例" | **必须拆**，各自独立 |
| **独立**：A 和 B 是并列关系，可各自深入 | "TCP 三次握手" vs "TCP 四次挥手" | **必须拆**，各自独立 |

#### 判断方法
- 能否用一句话概括核心？能 → 单一性合格
- 删掉某段后，剩余内容是否仍然完整？能 → 说明那段应独立成篇
- 拆成两篇后，每篇单独拿出来还有用吗？都有用 → 拆分合理；有一篇没用 → 不应拆分

### 1.2 自足性：打开即懂
- 读者无需翻阅其他笔记即可理解当前笔记的核心内容
- **禁止**纯指代性写法（如"如前所述""上面提到的"——这些词暗示了阅读顺序依赖）
- **允许**轻量化跳转指代：当某段内容属于基础公共知识且已有独立笔记时，可用一句话摘要 + 链接指代，不必重复展开

**轻量化跳转指代示例**：
```markdown
<!-- ❌ 纯指代（禁止） -->
如前所述，Python 的 GIL 限制了多线程并发……

<!-- ✅ 轻量跳转指代（允许） -->
Python 的 GIL（全局解释器锁）限制了多线程并发，[[Python GIL 机制|详见 Python GIL 机制]]。
```

#### 公共笔记引用
当多篇笔记都需要引用同一基础概念时，可将该基础概念写成独立公共笔记，其他笔记通过链接引用：
- **适用场景**：被 3 篇以上笔记共同引用的基础概念（如"GIL 是什么""Docker 镜像与容器的关系"）
- **引用方式**：一句话摘要 + 链接，不要求在每篇笔记中完整复述
- **注意**：公共笔记本身也必须满足原子笔记的全部规范

### 1.3 独立性：不依赖阅读顺序
- 笔记之间没有预设的阅读顺序
- 可以从任意笔记开始阅读，不会因为缺少"前置笔记"而读不懂

## 2. 笔记类型系统

本规范 3.2 的概念解释模板适用于 AI 辅助生成的原子笔记（type: 概念解释）。以下类型体系覆盖更多手写场景：

| type 值 | 含义 | 适用内容 | 模板 |
|---------|------|---------|------|
| `概念解释` | 概念定义 | 理论、原理、术语解释 | [[AtomicNote-概念解释]] |
| `步骤操作` | 操作步骤 | 配置、安装、部署流程 | [[AtomicNote-步骤操作]] |
| `故障排查` | 故障排查 | 问题诊断与解决方案 | [[AtomicNote-故障排查]] |
| `对比分析` | 对比分析 | 两种/多种方案的差异 | [[AtomicNote-对比分析]] |
| `面试知识点` | 面试知识点 | 面试常考点与标准回答 | [[AtomicNote-面试知识点]] |
| `极简速记` | 极简速记 | 灵感、碎片想法、临时记录 | [[AtomicNote-极简速记]] |
| `专题聚合页` | MOC 专题聚合页 | 多篇原子笔记的知识聚合页（见第 6 节） | [[MOC]] |
| `模板` | 可复用模板（Prompt / 配置 / 代码脚手架） | 系统提示词、配置模板、脚手架 | — |

> **枚举可扩展，但须经决策**：新建笔记时若内容无法归入以上 8 类，先按 [[指南-创建笔记]] Step 3 判断是否确有独立复用价值；确认需要新增 type 时，**必须同步更新本表与 `指南-创建笔记`**，禁止私自使用非标准值（如 `算法笔记` / `实战案例` 等均不在此枚举内，应归入最接近的现有类型）。

## 3. 笔记结构规范

### 3.1 标题规则
- 文件名 = 笔记标题，使用**简洁明确的名词短语**，中英文均可，不需要编号前缀
- 避免动词开头的标题（如"使用 Python 虚拟环境" → 改为"Python 虚拟环境"）
- 避免过于宽泛的标题（如"笔记""想法""记录"）
- 避免特殊字符：`<>/\|?*` 以及全角符号
- 多词间用短横线 `-` 分隔，同一知识库内保持一致
- 同一主题多版本时用 `-YYYYMM` 后缀区分历史版本，无后缀为当前有效版本

| ✅ 合格 | ❌ 不合格 |
|---------|----------|
| Python 虚拟环境配置 | 环境配置 |
| HTTP 状态码 403 与 404 | 状态码 |
| Obsidian 模板语法 | 模板 |
| Git-merge-冲突解决.md | git问题.md |
| Nginx-反向代理配置-202601.md | Nginx-反向代理配置-旧版.md |

### 3.2 正文模板

按内容类型选择对应模板。所有模板均可按需精简——省略不适用的章节，不必机械套用。

各类型模板已独立为文件，按需引用：

| type    | 模板文件                   | 适用内容             |
| ------- | ---------------------- | ---------------- |
| `概念解释`  | `[[AtomicNote-概念解释]]`  | 理论、原理、术语解释       |
| `步骤操作`  | `[[AtomicNote-步骤操作]]`  | 配置、安装、部署流程       |
| `对比分析`  | `[[AtomicNote-对比分析]]`  | 两种/多种方案的差异       |
| `故障排查`  | `[[AtomicNote-故障排查]]`  | 问题诊断与解决方案        |
| `面试知识点` | `[[AtomicNote-面试知识点]]` | 面试常考点与标准回答       |
| `极简速记`  | `[[AtomicNote-极简速记]]`  | 灵感、碎片想法、临时记录     |
| `专题聚合页` | `[[MOC]]` | 多篇笔记的知识聚合，详见 6 |

> 所有模板均可按需精简——省略不适用的章节，不必机械套用。

### 3.3 存放路径

写完笔记后，按 `[[分类映射表]]` 判定内容归属，放入知识库对应物理目录。Agent 执行顺序：查映射表 → 确定领域 → 写入文件。

**Knowledge 区两层封顶**：笔记直接存为 `Knowledge/AI/笔记名.md`、`Knowledge/Engineering/笔记名.md` 或 `Knowledge/Methods/笔记名.md`，不再开子目录。某主题 10+ 篇时建 MOC 聚合页，而非新建子目录。

## 4. 内容编写原则

### 4.1 用自己的话写
- 不要照搬原文——用自己的理解重新组织语言
- 如果是原文摘录，必须标注来源并区分摘录与自己的理解

### 4.2 具象化优先
- 能用具体例子说清的，不要只用抽象描述
- 能用代码/命令/配置片段说清的，不要只用文字描述
- 能用表格对比的，不要只用段落罗列

### 4.3 控制篇幅

| 笔记类型 | 建议字数 | 上限 |
|---------|---------|------|
| 概念解释 | 100~300 字 | 500 字 |
| 步骤操作 | 100~500 字 | 800 字 |
| 对比分析 | 100~400 字 | 600 字 |
| 极简速记 | 10~100 字 | 200 字 |
| 故障排查 | 100~500 字 | 800 字 |
| 面试知识点 | 200~600 字 | 1000 字 |

> **超过上限**：考虑拆分为多个原子笔记，或将详细内容移入长篇幅文档。

### 4.4 标记不确定内容
- 不确定的信息：标注 `⚠️ 未验证` 或 `？待确认`
- 有时效性的信息：标注有效时间（如 `截至 2026-04`）
- 个人观点与客观事实：个人观点明确标注"个人理解"/"个人实践"

## 5. 链接规范

### 5.1 链接类型

| 类型 | 含义 | 使用场景 |
|------|------|---------|
| **依赖链接** | 目标笔记是理解当前内容的**必要前提** | 当前笔记引用了一个需要先了解的基础概念 |
| **扩展链接** | 目标笔记提供**补充信息**，不读也不影响理解 | 相关但非必需的延伸阅读 |
| **对比链接** | 目标笔记是当前内容的**对照/替代方案** | 两种方案的对比、新旧方法的差异 |

```markdown
<!-- 依赖链接：明确标注前置关系 -->
> 前置知识：[[Python 装饰器]]

<!-- 扩展链接：轻量引用 -->
另见 [[Python 描述器]] 了解进阶用法。

<!-- 对比链接：明确标注对比关系 -->
与 [[for 循环]] 的性能对比见 [[Python 循环性能对比]]。
```

### 5.2 链接方向
- **向上链接**：指向更宏观的汇总聚合页
- **横向链接**：指向相关的概念笔记、对比笔记
- **向下链接**：指向更具体的底层细节笔记——通过依赖链接标注前置关系

### 5.3 链接与发布边界（硬规则）

**正文里禁止出现指向「非发布区」的 wikilink。**

发布面由 `.vitepress/config.ts` 顶部 `PUBLISHED_DIRS` 定义——只有 `vault/Knowledge/`、`vault/作坊/`、`vault/档案/` 会渲染到站点。指向 `vault/Resources/`、`vault/Memory/`、`vault/Inbox/`、`vault/Archive/`、`vault/DailyNotes/` 等目录的链接：

- 在 Obsidian 里**能跳转**（本地解析得到目标）→ 看起来一切正常，**极易漏检**
- 在站点上是**死链**（nolebase 渲染为 invalid-link）

**溯源一律写 frontmatter，不写正文。** frontmatter 不参与站点渲染，所以 `reference:` / `source:` 里指向剪藏原文是安全的；正文再写一次，就等于在站点上留一处死链。

| ❌ 正文禁止 | ✅ 正确做法 |
|---|---|
| `来源：[[AI personal growth app_中文]]（StarterStory 访谈）` | `来源：StarterStory 访谈（访问于 2026-09-21）`，并在 frontmatter 写 `reference: "[[AI personal growth app_中文]]"` |
| `原文存档于 [[人怎样才能学会深度思考？]]` | 删去该分句（`reference:` 已记录）或改为纯文字描述 |
| `原始研究报告见 [[…（原文）]]` | 同上；MOC 按 §6.4 不用 `reference`，正文只留文字 |

**例外**：显式写全路径、表明"这是素材库内部路径"的有意标注（如 `source: "[[Resources/OpenClaw/…]]"`）可保留——它只出现在 frontmatter。

**检查**：`python _agent_scripts/link_audit.py` 的「站点侧死链」段专扫此项，改完应为 0。

## 6. 专题聚合页

原子笔记是知识体系的叶子节点，专题聚合页是连接叶子的骨架。

### 6.1 什么是专题聚合页
专题聚合页（type: 专题聚合页）是一篇**汇总性笔记**，将散落在多篇原子笔记中的相关内容收拢到一个页面，形成某个主题的完整知识视图。与 MOC（Map of Content）概念等效。

### 6.2 何时创建聚合页
- 某个主题下已有 **3 篇及以上**原子笔记时，可创建聚合页
- 聚合页**不重复**原子笔记的内容，而是用简短描述 + 链接的方式组织

### 6.3 聚合页命名规范

- **文件名格式**：`[主题名]-MOC.md` — 主题名与 MOC 之间用短横线连接
- 示例：`RAG-MOC.md`、`Python-MOC.md`、`学习方法-MOC.md`
- **存放位置**：放在对应领域目录下，如 `Knowledge/AI/RAG-MOC.md`
- 文件名即为笔记标题，保持一致性

### 6.4 聚合页结构

使用模板 `[[MOC]]`。MOC 只需 5 个 frontmatter 字段：`title` / `created` / `tags` / `type` / `abstract`，不使用 `related`、`reference` 字段（关联笔记在正文表格中列出，来源在原子笔记中标注）。正文中禁止出现"由原大文件拆分为 N 篇"等拆分声明（同前置速查第 7 条）。

### 6.5 聚合页 vs 原子笔记

| 维度 | 原子笔记 | 专题聚合页 |
|------|---------|-----------|
| 粒度 | 单个概念/操作/问题 | 一个主题的全景 |
| 内容 | 原创知识内容 | 链接 + 简短描述 |
| 可独立阅读 | 是 | 否，需要点击链接阅读具体笔记 |
| 篇幅 | 有上限控制 | 无上限，随笔记增长自然扩展 |

## 8. AI 协作约定

当使用 AI 辅助编写原子笔记时：

1. **AI 负责拆分和重组**：提供原始素材（聊天记录、文章、截图等），AI 按本规范拆分为原子笔记
2. **AI 负责格式规范化**：将非结构化的文字整理为规范结构
3. **人类负责审核核心观点**：确保拆分后的内容准确反映原始意图
4. **AI 整理后不修改原始素材**：原子笔记是**衍生品**，原文保留在原位
5. **AI 可辅助清理**：季度复审时可让 AI 扫描笔记状态，生成清理建议清单，由人类确认后执行

## 附录：原子性自测——三秒法则

打开一个笔记，问自己：

> "如果我只看这个笔记，三秒钟能不能说出它在讲什么？"

- 能 → 原子性合格 ✅
- 不能 → 需要拆分或重写标题 ❌
