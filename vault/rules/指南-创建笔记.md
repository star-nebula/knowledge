# 场景指南：创建新笔记

> 创建新笔记时，按以下四步工作流执行。

---

## 操作步骤

### Step 1：分类判定与路径定位

判断内容属于哪个领域（AI / Engineering / Methods）或特殊归属（Projects / 面试），对照 [[分类映射表]] 确定物理存放路径。

分类判定请直接查阅 [[分类映射表]]，此处不冗余维护。

### Step 2：结构化提炼与过滤

- 过滤掉无用的废话、广告、情绪性评论
- 抽取最核心的 1-3 个知识点
- 评估知识点的实时性：如果是半年前的技术方案，在笔记中提醒"注意技术迭代，建议验证"

### Step 3：生成原子笔记

按 `原子笔记编写规范` 中对应类型的模板生成笔记：

- **先校验 type 标准枚举**：比对 `原子笔记编写规范` §2 的 8 类标准枚举（概念解释 / 步骤操作 / 对比分析 / 故障排查 / 面试知识点 / 极简速记 / 专题聚合页 / 模板）。
  - 能对应上 → 直接用该标准值，填写 Frontmatter（title/created/tags/type/related）。
  - **对应不上 → 先思考是否应新建 type（写入规则）**：判断该类型是否确有独立、可复用的价值（预计 ≥3 篇笔记会用到它）。
    - 有价值 → 提出**新增 type**，同步更新 `原子笔记编写规范` §2 枚举表与本指南，再使用新值；**禁止私自使用非标准值**。
    - 无独立价值 → 归入最接近的现有标准类型（如「算法笔记」「实战案例」分别归入 `概念解释` / `概念解释`）。
- 按模板编写正文

### Step 4：建立逻辑关联与保存

- 在笔记末尾关联同领域的 MOC（如 `[[RAG-MOC]]`），MOC 不存在时省略
- 保存到 Step 1 确定的路径
- **Knowledge 区两层封顶**：直接存为 `Knowledge/AI/笔记名.md`，不开子目录

---

## 检查清单

- [ ] Frontmatter 完整（title/created/tags/type/related）
- [ ] 标题符合规范（技术栈+概念+关键信息）
- [ ] 文件名与标题一致
- [ ] 内部链接使用 wikilink 格式 `[[文件名]]` 或 `[[文件名|显示文本]]`
- [ ] 外部链接使用标准 Markdown 格式 `[text](https://...)`，标注访问日期
- [ ] 核心内容自包含（代码/配置/踩坑在笔记内部）
- [ ] 存放路径符合分类映射表
- [ ] Knowledge 区未超过两层
