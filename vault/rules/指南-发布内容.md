# 指南-发布内容

> 触发场景：把内容发布到媒体平台，或要查「某内容发布在哪、发布过没有」时。
> **本文件已于 2026-09-21 整篇重写**——旧版通篇讲的 `vault/Published/` 体系**已废止**（该目录已不存在），不要再按旧版新建 `Published/` 或写 `[[Published/...]]` 引用。

## 〇、发布区不在 vault 里

发布区已于 **2026-09-14 迁出 vault**，现在在仓库外的 `E:\发布\`：

```
E:\发布\
└── <内容线>\
    └── <发布单元>（平台）\
        ├── <笔记>.md
        └── assets\
```

- 迁出意味着：**发布内容不再进 Obsidian**，vault 内的 `![[双链]]` 对它无效。
- 操作细则见发布区内的 `README.md`；本库不重复维护发布区结构。

## 一、结构规则

1. 顶层按**内容线**分（`AI 资讯` / `虚拟商品推销` / 未来的 `音乐收藏馆`…）。
2. 平台标注写在**发布单元文件夹名**里，形如 `2026-09-08（小红书、公众号）`。
3. 每个发布单元**自包含**：`.md` 与 `assets\` 同目录，便于整目录复制/交付。

## 二、命名规则

| 状态 | 文件夹名 | 例 |
|---|---|---|
| 未发布 | 只写主题，**不带日期与平台** | `AI生图公式\AI生图公式.md` |
| 已发布 | 补 `日期-主题（平台）` | `2026-09-14-AI生图公式（小红书）\2026-09-14-AI生图公式.md` |

日期与平台是「已发布」的**事实标记**，不是规划字段——没发布就不写。

## 三、链接规则

- 图片一律用**标准 markdown**：`![](assets/x.png)`。
- **禁用 Obsidian 双链** `![[x]]`：发布区已出 vault，双链不再被解析；标准链接在 VS Code / Typora / 任意预览器都能显示。

## 四、与其他目录的关系

- **不参与** `Inbox → Resources → Knowledge` 流转链——发布区是出口，不在知识库内。
- 与记忆库 `Memory/Projects/<项目名>/` 的区别：那边记「做了什么项目」，`E:\发布\` 放「对外发布了什么内容」。
