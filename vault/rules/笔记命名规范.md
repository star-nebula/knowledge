# 笔记命名规范

> Knowledge 区所有笔记平铺在同一目录，文件名是唯一的区分手段。命名需兼顾排序聚集、自解释、自然语序。

## 核心原则

| 原则 | 说明 |
|------|------|
| **排序友好** | 同类笔记按文件名排序自然聚集 |
| **自解释** | 脱离目录上下文也知所属领域 |
| **自然语序** | 中文"修饰语 + 核心词"顺序 |

## 分隔符：一律用连字符（定案 2026-09-21）

**标准 = 连字符 `-`**，用于领域前缀分隔与 MOC 后缀：`NLP-基础概念.md`、`Git-MOC.md`。

| | 说明 |
|---|---|
| 库内现状 | `Knowledge/` 266 篇中约 **111 篇含空格**（如 `Git 基础.md`）、98 篇含连字符——**空格名是历史遗留，不是标准** |
| 看到空格名时 | 不要跟着模仿；新笔记一律用连字符 |
| 存量空格名 | **冻结（2026-09-21 定案，不再迁移）**：空格名在 Obsidian 与全文检索下均正常可用，而脚本改名**不会更新 `[[wikilink]]` → 全库断链**，收益≈0、风险高。本规范**只管新增笔记**，存量一律不动 |

## 命名规则

### 有明确子领域归属的笔记

使用 **领域前缀 + 核心概念** 格式：

```
[子领域]-[核心概念].md
```

| 示例 | 说明 |
|------|------|
| NLP-基础概念.md | NLP 领域的基础概念 |
| NLP-文本预处理.md | NLP 领域的文本预处理 |
| 深度学习-基础概念.md | 深度学习领域的基础概念 |
| 机器学习-模型评估.md | 机器学习领域的模型评估 |

### 无子领域冲突的独立笔记

直接使用核心概念命名，不加前缀：

```
[核心概念].md
```

| 示例 | 说明 |
|------|------|
| Transformer.md | 只有一个，不需要前缀 |
| 注意力机制.md | 只有一个，不需要前缀 |
| DeepSeek.md | 独有，不需要前缀 |

### MOC 聚合页

```
[子领域]-MOC.md
```

| 示例 |
|------|
| NLP基础-MOC.md |
| 机器学习基础-MOC.md |

## 反模式（禁止）

| 反模式 | 问题 | 正确 |
|--------|------|------|
| `基础概念-NLP.md` | 后缀式，中文语序别扭，不聚集 | `NLP-基础概念.md` |
| `案例-NLP.md` | 同上 | `NLP-案例.md` |
| `机器学习 算法/KNN算法.md` | 子目录违反两层封顶 | `机器学习-KNN算法.md` |

## 命名去歧义流程

当两个子目录存在同名笔记时：

1. 确认内容是否不同 → 不同则必须去歧义
2. 为双方添加领域前缀（即使某一方原本不加前缀也不会冲突，也加上以保持一致性）
3. 更新所有引用该笔记的 wikilink
