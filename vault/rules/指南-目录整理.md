## 操作步骤

### 1. 评估当前结构

| 检查项 | 标准 |
|--------|------|
| Knowledge 目录深度 | **最多两层**（`Knowledge/AI/xxx.md`） |
| Projects 目录深度 | 最多三层（`Projects/xxx/notes/`） |
| Resources 组织 | 按来源分，不按文件类型分 |
| 文件数量 | 单个目录超过 20 个文件时考虑建 MOC（而非开子目录） |
| MOC 完整 | 某领域 10+ 篇笔记时有对应 MOC |

### 2. 确定操作类型

#### 新建 MOC（而非子目录）

当 `Knowledge/AI/` 下某主题笔记达到 10+ 篇时：
1. 创建 MOC 文件：`Knowledge/AI/[主题名]-MOC.md`（如 `RAG-MOC.md`）
2. 在 MOC 中列出所有相关笔记的 wikilink
3. 在相关笔记的 frontmatter `related` 中添加 MOC 引用
4. **不开子目录**——笔记仍在 `Knowledge/AI/` 下

#### 移动文件

1. 移动文件到新位置
2. Obsidian wikilink 会自动追踪同名文件移动
3. 如果文件被重命名，更新所有引用该文件的链接
4. 更新相关 MOC

#### 合并目录

1. 将文件移动到目标目录
2. 更新所有链接和 MOC
3. 删除空目录

### 3. 验证链接

整理完成后，验证：
- 所有内部链接是否有效
- MOC 中的链接是否正确
- 是否有孤立文件（未被任何链接引用）

## 动态分类规则

### Resources 新增来源

- **触发**：获得新的课程/书籍/系列资料
- **操作**：在 `Resources/` 下创建 `[来源名]/` 目录

### Resources 归档来源

- **触发**：某来源资料已全部转译为 Knowledge 笔记，且不再需要原始素材
- **操作**：整个来源目录移到 `Archive/`

### Knowledge 不新建子目录

- Knowledge 区**始终两层**，通过 MOC 聚合而非目录细分
- 如果某领域笔记过多，检查是否应该拆分为更原子的笔记
