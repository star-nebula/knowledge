# 场景指南：链接维护

> 维护 Obsidian 内部链接时，按以下步骤执行。

---

## 操作步骤

### 1. 检查链接类型

| 类型 | 格式 | 检查项 |
|------|------|--------|
| 内部笔记 | `[[文件名]]` 或 `[[文件名\|显示文本]]` | 目标文件存在、无同名歧义 |
| 消歧链接 | `[[目录/文件名\|显示文本]]` | 路径正确、目录对应实际位置 |
| 外部链接 | `[text](https://...)` | 链接可访问、标注访问日期 |

### 2. 修复断链

发现断链时：
1. 先确认目标文件是否仍存在于 vault 中（允许跨目录搜索同名文件）
2. 如果文件已移动但名称不变 → wikilink 自动追踪，无需修改
3. 如果文件已重命名 → 更新 wikilink 中的文件名
4. 如果文件已删除 → 决定是否删除链接或创建目标页面

### 3. 链接到 MOC

当需要引用一个主题领域的整体内容时，链接到对应的 MOC 文件：

- ✅ `[[RAG-MOC]]` — 链接到 MOC 文件
- ✅ `[[RAG-MOC|RAG 技术栈]]` — 带自定义显示文本
- ❌ `[RAG](Knowledge/AI/)` — 链接到目录，不可用

MOC 文件存放在对应领域目录下：
- `Knowledge/AI/RAG-MOC.md`
- `Knowledge/Engineering/Python-MOC.md`
- `Knowledge/Methods/学习方法-MOC.md`

### 4. 同名文件消歧

当 vault 中存在多个同名 `.md` 文件时，需在 wikilink 中附加路径消歧：

- ✅ `[[Knowledge/AI/Transformer 架构|Transformer]]` — 多个同名时消歧
- ✅ `[[Python 数据结构]]` — 文件名唯一时无需路径

### 5. 验证外部链接

外部链接需要定期验证：
1. 检查链接是否可访问
2. 如果失效，寻找替代链接
3. 更新访问日期

### 6. 发布边界检查（建链 / 改链后必做）

正文（会渲染到站点的部分）**不得**出现指向「非发布区」的 wikilink —— `vault/Resources/`、`vault/Memory/`、`vault/Inbox/`、`vault/Archive/`、`vault/DailyNotes/` 等。

这是**唯一"看不见"的断链类型**：目标文件确实存在，所以在 Obsidian 里能正常跳转，只有在站点上才是死链。

- **溯源写 frontmatter**：`reference:` / `source:` 不随站点渲染，指向剪藏原文是安全的
- **正文提来源用文字**：写 `来源：StarterStory 访谈（访问于 2026-09-21）`，不要带 `[[]]`
- **检查**：`python _agent_scripts/link_audit.py` → 看「站点侧死链」段是否为 0
- **规则正本**：[[原子笔记编写规范]] §5.3

## 常见问题

### 问题 1：链接到目录而非文件
**错误**：`[RAG](Knowledge/AI/)`
**修复**：`[[RAG-MOC]]` — 改为链接到该领域的 MOC 文件

### 问题 2：使用旧 Markdown 路径链接
**错误**：`[Python 数据结构](../基础语法/Python 数据结构.md)`
**修复**：`[[Python 数据结构]]` — 文件名唯一时直接用 wikilink，无需路径

### 问题 3：MOC 未消歧
**错误**：`[[MOC|RAG]]` — vault 中存在多个 MOC 文件，Obsidian 无法确定目标
**修复**：`[[RAG-MOC|RAG]]` — 使用完整文件名消歧

## 检查清单

- [ ] 内部链接使用 wikilink 格式 `[[文件名]]` 或 `[[文件名|显示文本]]`
- [ ] 外部链接使用标准 Markdown 格式 `[text](https://...)`
- [ ] 所有链接指向 `.md` 文件，而非目录
- [ ] 同名文件已用路径消歧
- [ ] 外部链接标注访问日期
- [ ] 无断链（wikilink 目标文件存在）
- [ ] 正文无指向非发布区的链接（Resources/ Memory/ 等；溯源一律写在 frontmatter）
