# 场景指南：健康检查

> 定期执行健康检查，确保知识系统质量。

---

## 检查项目

### 1. 链接完整性检查

检查所有内部链接是否有效：

**检查项**：
- [ ] 链接目标文件存在
- [ ] 路径格式正确（使用 wikilink）
- [ ] 特殊字符用 `< >` 包裹
- [ ] MOC 索引文件引用的底层笔记全部存在

### 2. Frontmatter 检查

**检查项**：
- [ ] 所有 Knowledge 下的笔记有 frontmatter
- [ ] 必填字段完整（title/created/tags/type/related）
- [ ] `created` 字段与内容时效性匹配

### 3. 标题规范检查

**检查项**：
- [ ] 标题包含足够的上下文信息
- [ ] 文件名与标题一致
- [ ] 无过于简单的标题（如 "笔记"、"问题"）

### 4. 目录结构检查

**检查项**：
- [ ] Knowledge 目录深度不超过**两层**（`Knowledge/AI/xxx.md`）
- [ ] Projects 目录深度不超过三层
- [ ] 10+ 篇笔记的主题有 MOC 索引
- [ ] Resources 按来源组织，不按文件类型
- [ ] 无空目录（超过 60 天）

### 5. 笔记粒度检查

**检查项**：
- [ ] 无超长文件（超过对应类型字数上限，见 `原子笔记编写规范`）
- [ ] 无过短文件（少于 10 行，除非是索引/速记）
- [ ] 同类知识点已聚合

### 6. 孤立文件检查

检查是否有未被任何 MOC 或链接引用的文件：

**检查项**：
- [ ] Knowledge 下所有文件至少有一条反向链接
- [ ] 无"丢失"的文件

### 7. Inbox 清空检查

**检查项**：
- [ ] Inbox 中无超过 7 天未处理的闪念笔记
- [ ] 有处理计划或已清空

---

## 执行频率

| 检查项 | 建议频率 |
|--------|---------|
| 链接完整性 | 每次大规模更新后 |
| Frontmatter | 每周一次 |
| 标题规范 | 每月一次 |
| 目录结构 | 每月一次 |
| 笔记粒度 | 每季度一次 |
| 孤立文件 | 每月一次 |
| Inbox 清空 | 每周一次 |

---

## 问题修复

| 优先级 | 问题 | 修复方式 |
|--------|------|---------|
| P0 | 断链 | 立即修复路径或创建目标文件 |
| P0 | Frontmatter 缺失 | 立即补充 |
| P0 | Inbox 超期未处理 | 立即处理或归档 |
| P1 | 标题不规范 | 重命名文件和标题 |
| P1 | 目录结构混乱 | 整理目录结构 |
| P1 | Knowledge 超两层 | 去掉子目录，改用 MOC |
| P2 | 笔记粒度不当 | 考虑拆分或合并 |
| P2 | 孤立文件 | 添加到 MOC 或删除 |
